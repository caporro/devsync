# 0.1.30 — release and upgrade notes

Release tag: `v0.1.30`. Docker image: `caporro/devsync:0.1.30` (`linux/amd64` and `linux/arm64`). The tag pipeline publishes the image after validation.

## Fix since v0.1.29

[PR #2](https://github.com/caporro/devsync/pull/2), contributed by Ildeias, fixes recognition of historical truncated task filenames during explicit maintenance.

`dateStamp()` writes timestamps without milliseconds, such as `2026-10-01T13-21-59Z-…`. The filename-repair pattern previously required milliseconds, so these files were ignored and a dry run could report zero candidates. Repair now accepts timestamps both with and without the three-digit milliseconds component.

The regression test covers two 140-character filenames without milliseconds, including one truncated at the dot before its extension. It verifies preview discovery, collision-safe Markdown destinations and preservation of task ID, completion state and owner. Existing filename-length, UTF-8 and task-content recognition checks remain in place.

This is the only functional change since 0.1.29. The Windows `mentions.test.js` cleanup issue remains separate.

## Upgrade and repair

Update the code/image to 0.1.30 while retaining the existing data mount and vault configuration. No additional data-format migration is introduced. Filename recovery is an explicit operation and does not run automatically during ordinary reads.

If a previous repair found no files or recovered only part of a vault, rerun the preview with the same vault environment and data mount. The production image includes the maintenance script:

```sh
node scripts/migrate-tasks.mjs --repair-filenames --dry-run
```

After inspecting the preview, stop normal HTTP/stdio writers and back up the complete data directory outside the active volume, then apply the repair using the same configuration:

```sh
node scripts/migrate-tasks.mjs --repair-filenames
```

The operation can be rerun to pick up remaining candidates. Existing repair and migration backups remain under `tasks/.filename-repair/` and `tasks/.migration-v2/`. A completion state previously lost by older software can only be recovered from a surviving original index or backup.

See the [full maintenance procedure](0.1.28.md#upgrade-procedure), [task recovery contract](../reference/tasks.md) and [0.1.29 feature notes](0.1.29.md).
